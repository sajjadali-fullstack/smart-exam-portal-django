1️⃣ Step 1: Brainstorming & Database Blueprinting (models.py)

1. Kisi bhi project ki neenv (foundation) uska data hota hai. Pehle pen-paper par ya dimaag mein socho ki tumhe kya-kya save karna hai.
2. Samajhne ka tarika: Pehle Category aayegi, phir har question kisi na kisi category se linked hoga (ForeignKey), aur end mein jab user test dega toh ek TestResult table banegi jo user, category aur marks ko ek sath stretch karegi.
3. Action: Sabse pehle hamesha Django models bante hain, migrate hote hain, aur admin panel par register hote hain.

2️⃣ Step 2: Routing the Paths (urls.py)

0. Jab database ready ho jaye, toh socho ki user tumhari website par kahan-kahan ghumega (URLs mapping).
1. Samajhne ka tarika: Homepage par (''), quiz page par category aur difficulty ke dynamic values ke sath (quiz/<str:category_name>/<str:difficulty>/), aur dashboard par (dashboard/).
2. Action: URL endpoints structure ready karna.

3️⃣ Step 3: Pure Core Logic Handling (views.py)

0. Yeh tumhare project ka dimaag (CPU) hai. Data aur Frontend ke beech ki kadi yahi hai. Ismein teen cheezein serial wise banti hain:

1. GET Request Logic: Database se questions filter karke screen par dikhana.
2. POST Request Logic: User ne jo submit kiya, uspar loop chala kar sahi answers check karna, percentage calculate karna(
    percentage = coorect / total_questions * 100
)aur database mein save karke redirect karna.

4️⃣ Step 4: The Interface Canvas (templates)

0. Jab backend ka data views se pass ho jata hai, tab bari aati hai use sundar dikhane ki.
1. Samajhne ka tarika: Pehle base.html banao taaki bootstrap setup baar-baar na karna pade. Phir templates ko {% extends %} karo.
2. Radio buttons mein name="q_{{ q.id }}" attributes ka dhyan rakhna, kyunki yahi backend par data fetch karne ke kaam aata hai aur ek baar mein ek hi option select karne deta hai.

5️⃣ Step 5: Adding Client-Side Intelligence (JavaScript)

0. Jab tumhara static page load hone lage, tab usmein interactivity daalo.
1. Samajhne ka tarika: Browser mein setInterval chalana taaki har second time kam ho, aur document.getElementById('form-id').submit() trigger karna jab time zero ho jaye.

6️⃣ Step 6: Securing & Personalizing (Authentication)
0. Jab core functionality chalne lage, tab system mein security (Login/Register) aur user-specific data filtering add karo.
1. Samajhne ka tarika: @login_required lagana taaki unauthenticated users access na kar sakein, aur template mein {% if user.is_authenticated %} se navbar badalna.

💡 Interviewer ko kya impress karega? (Your Selling Points)
1. Relational Database Design (models.py)
Tum unhe bata sakte ho: "Sir, maine database ko extendable banaya hai. Ek Category model hai jo Question se One-to-Many (ForeignKey) relationship se juda hai. Iska fayda yeh hai ki kal ko agar 50 nayi categories bhi aayengi, toh backend code ko bina chhede dynamic scaling ho jayegi."

2. State Management & Filtering Logic
Tumne views.py mein dynamic filtering lagayi hai URL slugs (<str:category_name>/<str:difficulty>/) ke base par. Yeh dikhata hai ki tumhe Django mein Clean Routing aur query optimization (jaise .filter()) ki achhi samajh hai.

3. Backend-Frontend Synchronization (The Timer)
Interview mein yeh sawaal bohot banta hai: "Agar user page reload karde ya time khatam ho jaye, toh cheat prevent kaise karoge?" Tum chhati thonk ke bol sakte ho: "Maine frontend par JavaScript countdown lagaya hai jo secure backend validation se connected hai. Jaise hi time 0 hota hai, browser DOM event trigger karke form ko automatically POST kar deta hai."
